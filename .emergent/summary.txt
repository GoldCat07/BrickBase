<original_problem_statement>
The user wants to build a comprehensive real estate mobile application with an accompanying web-based admin dashboard.

**PRODUCT REQUIREMENTS:**

**Mobile App:**
1.  **Authentication:**
    *   Mobile number and OTP-based sign-up/login.
    *   A static OTP of  should be used for testing.
    *   Request location access before the sign-up form to auto-fill the user's city.
    *   Sign-up form must collect: Name, Firm Name, City of Operations, and Email.
2.  **Organization & Subscriptions:**
    *   A tiered subscription model: Pro Owners can create organizations and add employees.
    *   Non-pro users are prompted with an upsell screen (Go Pro) if they try to create an organization.
    *   **Pricing (to be controlled from the backend, not hardcoded):**
        *   **Pro Owner Plan:** ₹3599/month (or ₹2999/month if billed annually at ₹35990).
        *   **Employee Seats (paid by owner):**
            *   Up to 7 employees: ₹399/user.
            *   8-14 employees: ₹759/user.
            *   Above 14 employees: ₹1299/user.
    *   Pro owners can generate and share an organization invite link.
3.  **Employee Onboarding:**
    *   The invite link should use deep linking: open the app if installed, or redirect to the App/Play Store if not. After installation, the app should open and process the invite.
    *   Employees sign up with their mobile and OTP.
    *   A Congratulations pop-up will show they've been invited to the specific organization.
    *   The firm name in the employee's profile should be pre-filled and non-editable.
    *   The organization owner should receive a push notification when a new employee joins.
4.  **Organization Management:**
    *   Owners can view and remove members.
    *   Employees can only view members.
    *   The member list should display a profile photo, name, and mobile number.
    *   All users should be able to add a profile photo.
5.  **Payment & Security:**
    *   Use Razorpay for payments (to be implemented later).
    *   If a payment fails, a persistent, blocking pop-up should appear on every app launch until the payment is successful.
    *   A mobile number should only be logged into one device at a time.

**Admin Dashboard (Web):**
1.  **Backend:** Use Supabase (PostgreSQL) for the database, auth, and storage. The dashboard will be the control panel for the entire application.
2.  **UI/UX:**
    *   A spreadsheet-like view of all Pro Owners.
    *   Columns: Name, Mobile Number, Firm Name, Subscription Status.
    *   The list should be filterable by city and sign-up date.
    *   Clicking on a user row opens a detailed view to manage their subscription, pro status, and the number of employee seats.
    *   Admins should also be able to view properties associated with a firm from this view.
3.  **Dynamic Pricing Control:**
    *   A section to manage plan pricing on a city-by-city basis for a predefined list of cities (Faridabad, Gurugram, Noida, Delhi, etc.).
    *   Include categories for 'Other Cities' and 'International' to manage pricing for users outside the specified list.
4.  **Database:** All database tables should have  and  timestamps.

**Code Architecture**


**Key Technical Concepts**
- **Tech Stack:** Expo (React Native), FastAPI (Python), Supabase (PostgreSQL).
- **Authentication:** JWT-based stateless authentication flow initiated by a mobile OTP verification.
- **Routing:** File-based routing using .
- **Database:** Supabase for PostgreSQL database and user management.
- **API Design:** RESTful API built with FastAPI and Pydantic for data validation.
- **Dynamic Pricing:** Pricing logic is handled on the backend and fetched by the client, allowing for changes without an app update.

**key DB schema**
- **users:** {id, mobile, name, firm_name, city, email, created_at, updated_at, organization_id}
- **organizations:** {id, name, owner_id, created_at, updated_at}
- **subscriptions:** {id, user_id, plan_type, status, start_date, end_date, employee_seats}
- **pricing:** {city, pro_owner_monthly, pro_owner_annual, employee_tier_1, ...}
